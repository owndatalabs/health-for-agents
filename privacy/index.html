Health for Agents

Privacy Policy

Effective date: July 4, 2026

Health for Agents is designed to keep users in control of their Apple Health data. The app reads HealthKit data only after the user grants permission in iOS. The app does not include advertising, third-party analytics, tracking SDKs, or a developer-operated server backend for collecting health data.

Data the app can access

With the user's explicit permission, Health for Agents can read health and fitness data from Apple HealthKit. This may include sensitive information such as activity, workouts, sleep, heart rate, body measurements, nutrition, and other HealthKit records that are available on the user's device.

How Health data is used

Health data is used only to provide the app's core features: showing a limited debug preview, creating local JSON or ZIP exports, sharing an export through the iOS share sheet, and sending selected recent data to an AI agent API endpoint configured by the user.

What can be sent to an agent endpoint

If the user chooses Send to Agent, the app sends only the selected recent range: 24 Hours, 7 Days, or 30 Days. The JSON payload can include HealthKit sample identifiers, sample type identifiers, start and end dates, numeric or category values, units, text values, metadata when present, export metadata such as schemaVersion, generatedAt, scope, and source, and a short instruction asking the receiving agent to analyze trends and avoid medical diagnosis.

If the user saved an API bearer token in the app, the token is sent only as an Authorization header to the configured endpoint. The bearer token is not included inside the JSON HealthKit export.

Local storage and exports

Export files are created locally on the user's device. Old exports are deleted automatically when the app starts, and users can manually delete existing exports from inside the app. When a user shares or saves an export through iOS, the user chooses the destination and is responsible for what happens to that exported file afterward.

Sending data to an AI agent

The app can send recent HealthKit data to an HTTPS API endpoint entered by the user. Health for Agents does not include, operate, select, or control a third-party AI service or developer-operated backend. The recipient is the exact endpoint URL entered by the user. Before an in-app Send to Agent transfer, the app shows a review screen that identifies the recipient URL, explains the categories of HealthKit data being sent, and asks the user to confirm the transfer.

If the user-configured endpoint forwards data to an AI provider, stores the data, logs the data, or shares the data with another service, that behavior is controlled by the endpoint owner, not by Health for Agents. Users should only send health data to endpoints and AI services they control or trust, and whose privacy and security practices provide appropriate protection for sensitive health data.

The app stores the optional API bearer token locally in the iOS Keychain. The token is used only to authenticate requests to the user-configured AI agent API endpoint.

Shortcuts automations

Users may configure Apple Shortcuts to trigger a health update. Before saving Shortcut automation settings in the app, Health for Agents shows a one-time review screen explaining that future Shortcuts can send HealthKit samples from the saved range to the saved endpoint, including from user-created automations. Shortcut runs do not show an in-app confirmation every time. When a Shortcut runs, it uses the saved endpoint, selected time range, and bearer token from the app settings. If the endpoint or range changes, the user must save and approve the automation settings again. Whether an automation runs depends on iOS Shortcuts behavior and the user's device settings.

No tracking or advertising

Health for Agents does not use advertising identifiers, does not track users across apps or websites, and does not sell user data. The app does not include third-party analytics SDKs.

Data retention and deletion

The app keeps only the local settings needed to operate, such as HealthKit access state, the configured API endpoint, selected shortcut range, and the optional bearer token in Keychain. Users can remove exported files from inside the app. Users can revoke HealthKit access at any time in the iOS Settings app.

User responsibility after export or transfer

Health data is sensitive. After a user exports, shares, saves, or sends data outside the app, the user is responsible for the chosen destination and recipient. Users should avoid sending health data to services or people they do not fully trust.

Legal Basis (GDPR)

The processing of your HealthKit data is based strictly on your explicit consent (Art. 6(1)(a) and Art. 9(2)(a) GDPR), which you grant when allowing HealthKit permissions in iOS and triggering an export or setting up an automated transfer. You can revoke your consent at any time by disabling HealthKit access for this app in the iOS Settings.

Your Rights

Under applicable data protection laws (such as the GDPR), you have the right to access, rectify, or request the erasure of your personal data. Because Health for Agents does not store or transmit your data to any developer servers, all health data remains on your device. You can exercise your rights directly by deleting exported files in the app, clearing app settings, or removing the app from your device. You also have the right to lodge a complaint with a data protection supervisory authority.

Not a Medical Device

Health for Agents is purely a technical data export utility. It is not a medical device, does not offer medical advice, diagnosis, or treatment, and is not intended to replace professional medical judgment.
